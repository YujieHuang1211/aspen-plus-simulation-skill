# 交叉验证：Aspen 和搭档工具怎么分工

## 1. 原则

- **每个数字只有一个"主算"工具**，其他工具做复核。不要让两个工具各算一半、在报告里拼起来，出了偏差说不清是谁的问题。
- **复核要走独立路径**：不同的程序、不同的热力学数据或不同的推导方法。同一个 Aspen 模型换个物性方法再跑一遍，算不上独立复核。
- **先各自落盘，再比对**。先比对再写结论，很容易不自觉地往一边靠。
- **判据看量级和来源**：
  - 偏差在 1%～2% 以内，并且能说清来源（数据库不同、某个压力取值不同），就算互证成立；
  - 偏差几个百分点，要逐项定位，定位不了就如实写成不确定度；
  - 差一个量级，必有一方错，找第三条路径（手算、文献值、另一个程序），不许挑一个顺眼的用。

## 2. 分工表

| 工具 | 主算什么 | 不该用它算什么 | 和 Aspen 的接口 |
|---|---|---|---|
| Aspen Plus | 全厂（BOP）物料 / 能量平衡：预热、换热、分离、压缩、公用工程 | 淬冷或动力学控制的反应区转化率；流场 | — |
| Cantera | 有限速率动力学：0 维热区 + 规定降温速率的淬冷、点火延迟、停留时间敏感性 | 带相变、分离的流程 | 算出的单程转化率填进 Aspen 的 RStoic；进料组成和温度从 Aspen 物流取 |
| NASA CEA（`cea` Python 包） | 独立的化学平衡：高温、离子化、燃烧产物 | 动力学、流程 | 和 Aspen RGibbs、Cantera 平衡态三方对比同一组 T、P、进料 |
| Fluent / CFX | 流场、混合、停留时间分布、局部热点、壁温 | 全厂平衡 | 边界条件取 Aspen 物流；算出的停留时间分布反过来检验 Aspen / Cantera 的"充分混合"假设 |
| HTRI | 换热器详细校核：传热系数、压降、振动、几何 | 流程平衡 | 负荷和两侧物流条件取 Aspen；两者总负荷应一致，传热系数和压降以 HTRI 为准 |
| Python 手算脚本 | 独立重算关键平衡：焓差、元素守恒、冷凝量 | — | 对 Aspen 的 BOP 结果逐项比对 |
| Aspen HYSYS | 油气 / 炼化流程、动态模拟 | — | 本技能不展开；需要时参考 Codex 侧 `aspen-simulation-designer` |

## 3. 什么时候必须叫搭档

| 信号 | 叫谁 |
|---|---|
| 反应靠淬冷"冻结"产物：等离子体、电弧、激波、燃烧后急冷 | Cantera |
| 温度高于约 3000 K，或者有电离 | NASA CEA（`ions=True`）；Aspen 的数据库在这个温度区间多半要外推 |
| 换算出的平衡转化率要写进对外文件 | NASA CEA 或 Cantera 平衡态，至少一条独立路径 |
| 混合距离短、停留时间短（毫秒级），或者有明显的冷热分区 | Fluent |
| 换热器是非标几何（套管夹套、紧凑式、异形通道），或者压降、振动是卖点 | HTRI |
| 报告里的数字要拿去报价或写保证值 | 至少用 Python 手算复核一遍 BOP 平衡 |

都不满足时，Aspen 单算加上 `model-building.md` §6 的五项自查就够了，不要为了"多一层保险"叫一堆工具。

## 4. 工具使用的坑

**Cantera**

- 机理文件的热力学多项式有适用温度上限（GRI-Mech 系列一般到 3500～5000 K）。P47 里 Cantera 平衡在 8000 K 以上返回 NaN，那部分只能用 CEA。
- 0 维模型的降温历程是人为规定的（线性或指数，速率 q K/s），结论要写成"在 q = … 时"。q 本身要么来自 CFD，要么作为敏感性参数扫一遍。
- 需要的物种不在机理里（比如 C(s)、NOx 某些中间体）时，结果会悄悄缺项，先列出机理物种清单核对。

**NASA CEA（Python 包 `cea`）**

- 高温要开 `ions=True`，否则 5000 K 以上的组成会偏。
- 每个温度点新建一个 `EqSolution`。复用同一个对象连续求解，上一个点的残留状态可能让下一个点不收敛或结果漂移。
- 输出的是摩尔分数字典，物种名和 Cantera 不完全一样（电子是 `e-`），比对前统一命名。

**Fluent**

- 售前阶段通常不做完整 CFD，只在流场确实决定方案成败时才上。工作目录用纯 ASCII 路径。
- 结果要回到 Aspen 能用的形式：停留时间分布、出口平均温度和组成、壁面热流。

**HTRI**

- 输入从 Aspen 导出的物性表（或直接用 HTRI 内置物性），两边物性不一致时以哪边为准，要在报告里写明。

## 5. 参考案例：P47 等离子体 CO₂ 还原（100 kW 单炬，售前）

| 环节 | 主算 | 复核 | 结果 |
|---|---|---|---|
| 平衡上限（CO₂ 热解、CO₂ + 2H₂） | Cantera 平衡 | NASA CEA；Aspen RGibbs | CEA 与 Cantera 在 1500～6000 K 吻合（3000 K 时 CO 摩尔分数 0.361 对 0.362）；RGibbs 平衡转化率比 NASA 数据低 0.1～0.2 个百分点，属数据库差异 |
| 单程转化率（热区 + 淬冷） | Cantera 0 维有限速率模型 | 无独立路径，做了淬冷速率和冻结温度敏感性 | RWGS 单程转化率被约 2000 K 的冻结温度锁定在 82%～87%；规格书要求的 92% 单程不可达 |
| 全厂热质平衡 | Aspen Plus（RStoic 用 Cantera 的转化率） | Python 独立焓平衡脚本 | 反应器负荷 15.989 对 15.997 kW，回热器 15.258 对 15.256 kW，水冷器 13.93 对 13.86 kW（差 0.4%，来自分离器压力 1.05 对 1.02 bar(a)），冷凝水 13.44 对 13.34 kg/h |
| 换热器 | 未做 HTRI | — | 售前阶段只给负荷，HTRI 留到详细设计 |
| 流场 | 未做 CFD | — | 淬冷速率作为假设参数写进报告和澄清清单 |

这个案例说明三件事：

1. 反应区和 BOP 分开算是对的。直接用 RGibbs 代替反应器会卡在"取哪个温度"上：取出口温度（700 ℃），平衡往回移，转化率明显偏低；取热区温度，又不知道该取多少。真实转化率由冻结温度决定（本例约 2000 K，RGibbs 在该温度下给出 86%，恰好落在动力学结果的范围里），而冻结温度只有动力学模型给得出来。
2. 偏差 0.4% 时去找原因，找到了（分离器压力取值不同），就写进报告，不需要改模型。
3. 没有做的复核（HTRI、CFD）在报告里写明"未做、原因、哪个阶段做"，不要留白让读者以为做过。

## 6. 记录格式

每次复核都要在报告或计算书里留一行，字段固定：

| 量 | 主算工具与结果 | 复核工具与结果 | 偏差 | 偏差来源 | 结论 |
|---|---|---|---|---|---|
| 反应器热负荷 | Aspen RStoic，15.989 kW | Python 焓平衡，15.997 kW | 0.05% | — | 互证成立 |
| 水冷器热负荷 | Aspen，13.93 kW | Python，13.86 kW | 0.4% | 分离器压力 1.05 / 1.02 bar(a) | 互证成立，取 Aspen 值 |

对外文件只写结论和偏差，不写工具名和内部脚本名时，按项目自己的外发规则处理。
